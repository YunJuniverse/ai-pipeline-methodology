# 29. 자율주행 모드 — 장시간 자율 턴의 기획과 루프

> "8시간 자율주행" 처럼 **시간을 주면 그만큼의 일을 스스로 기획하고 루프를 도는** 운영 모드.
> 위상: 지침 07(예산·정지조건)의 *실행 형태*. 07이 "얼마나 쓰고 언제 멈추나"라면 이 지침은 "그 예산으로 무엇을 어떤 순서로 도는가".
> 핵심 가치: **시간은 예산의 단위이지 채워야 할 할당량이 아니다.** 일이 끝나면 일찍 끝내고, 안 끝나면 남긴 것을 보고한다.

---

## 1. 무엇이 기계로 강제되고 무엇이 계약인가 (먼저 알 것)

지침 07 §5.2가 이미 규명했다 — 6개 서킷브레이커 중 **런타임이 강제하는 건 반복수·비용·권한범위 3개뿐**이고, wall-clock·에러율·사람 에스컬레이션은 **운영 계약**이다.

→ **"8시간"은 기계가 지키는 상한이 아니다.** 타이머가 8시간에 멈춰 세워 주지 않는다. 시간은 ① 몇 사이클을 기획할지의 *환산 단위* ② 사람이 언제 돌아와 볼지의 *약속*으로만 쓴다. 이건 결함이 아니라 요구사항과 일치한다 — 시간을 다 채울 필요가 없기 때문이다.

## 2. 사전 요구 (없으면 루프가 첫 사이클에서 멈춘다)

| 요구 | 왜 | 없으면 |
|---|---|---|
| **권한 사전 승인** | 무인 실행 중 권한 프롬프트가 뜨면 거기서 정지 | 사람이 자리에 없는 8시간 = 8시간 대기. **최대 실무 장애물** |
| **샌드박스 경계(지침 28)** | 루프가 스키마·인증·과금을 건드리면 Class B/C에서 멈춤 | 운영 코드에서 자율주행은 30분마다 멈춘다 |
| **컴팩션 앵커(지침 06)** | 8시간이면 컨텍스트 요약이 여러 번 발생 | 요약이 계획을 잃으면 루프가 방향을 잃고 이미 한 일을 다시 함 |
| **ground-truth 판정 수단** | 진척을 자기평가로 판정하면 안 됨(지침 07 §5.3) | 에이전트가 "형편없는 결과를 자신있게 칭찬"하며 8시간 헛돎 |

> 넷 중 **권한과 샌드박스는 착수 전에 확인하고, 없으면 자율주행을 시작하지 않는다.** 나머지 둘은 루프 안에 장치로 박는다(§4).

## 3. P0 — 시간 예산을 작업 기획으로 환산

루프를 돌기 전에 **기획을 먼저 끝낸다**. 기획 없는 루프는 그냥 방황이다.

1. **시간 → 사이클 수 환산.** 1 사이클 = 개발 → 검토 → QA → 신규작업 도출. 경험 기준 **1 사이클 ≈ 45~90분**(작업 크기에 따라). 8시간이면 5~8 사이클.
2. **작업 목록을 사이클 크기로 자른다.** 한 사이클에 안 끝나는 덩어리는 쪼갠다. 쪼갤 수 없으면 자율주행 대상이 아니다(사람과 같이 할 일).
3. **의존 순서를 박는다.** 병렬 가능한 것과 선행이 필요한 것을 구분 — 병렬분은 서브에이전트 팬아웃(지침 08) 후보.
4. **예산을 이중 선언**(지침 07 §5.1): runtime(사이클 수·비용) + declared scope(파일 수·PR 수).
5. **정지 조건을 명문화**한다 — §5.
6. **기획을 파일로 남긴다** — `40_dev/snapshots/<date>_autopilot-plan.md`. 컴팩션이 대화를 잃어도 이 파일이 살아남는다.

> 기획 자체가 첫 사이클을 먹는다. 8시간 선언이면 기획에 30~60분을 쓰고 남는 시간으로 사이클 수를 다시 계산한다.

## 4. 루프 — 1 사이클의 4단계

```
[1 개발] → [2 검토] → [3 QA] → [4 신규작업 도출] → 다음 사이클
```

### 1. 개발
- 기획에서 다음 항목 1개를 꺼낸다. **한 사이클에 한 항목** — 여러 개를 동시에 열지 않는다(실패 시 원인 분리 불가).
- 완료 기준은 착수 시점에 문장으로 고정한다("무엇이 되면 이 항목이 끝났다고 할 것인가").

### 2. 검토
- **생성과 평가를 분리한다**(지침 07 §5.3). 방금 짠 코드를 같은 맥락에서 자평하지 않는다.
- 실무형: 독립 검토 패스를 별도 컨텍스트로 돌린다(서브에이전트 또는 새 판단 단계). 검토 관점을 명시적으로 다르게 준다 — 정확성 / 경계조건 / 이 변경이 깨뜨릴 수 있는 것.
- 수거 캡슐 `guard-pass-verdict-is-weak`: **판정기의 '통과'는 '거부'보다 훨씬 약하다**(실측 거부 86건 전부 타당 vs 통과 10건 중 5건 가짜). 통과를 최종 판정으로 쓰지 않는다.

### 3. QA — ground-truth로만 판정
- **환경 상태로 판정한다**: 테스트 통과 수, 빌드 성공, 린트, 실제 렌더/실행 결과, diff. 모델의 자기보고는 진척 증거가 아니다.
- 화면이 있는 작업은 **실제로 띄워서 본다**(빌드 통과 ≠ 렌더 정상 — 수거 캡슐 `verify-source-not-proxy`의 3실사례).
- 성능 주장은 워밍 후 다회 표본 중앙값 + 분산 — 규범 정본은 **지침 23 §2-4**(자율주행 전용이 아니라 일반 규범으로 승급됨).
- QA 실패 시: 같은 항목 **최대 2회** 재시도. 3회째 금지(지침 07 no-progress) → 그 항목을 `## Blocked`로 내리고 다음 항목으로.

### 4. 신규작업 도출
- 이번 사이클에서 *발견된 것*을 다음 작업으로 만든다: QA가 잡은 결함, 검토가 지적한 구조 문제, 하다 보니 드러난 선행 조건.
- **분류해서 넣는다** — 이번 자율주행 범위 안이면 기획 목록에 삽입, 범위 밖이면 TODO Backlog, 사람 판단이 필요하면 `## Blocked`.
- 마찰을 겪었으면 `observe --friction`. 이게 다음 자율주행을 더 낫게 만드는 유일한 경로다.
- **사이클 로그 1줄**을 checkpoint에 남긴다 — `[C3] 항목 / 결과 / 다음`. 컴팩션 생존 앵커.

## 5. 정지 조건 — 시간보다 먼저 오는 것들

아래 중 하나라도 걸리면 **시간이 남아도 멈추고 보고**한다:

| 조건 | 판정 |
|---|---|
| **no-progress 2회** | 같은 항목·같은 실패에서 2회 진전 없음 (지침 07 §2) |
| **예산 초과** | 선언한 사이클 수·파일 수·PR 수 초과 |
| **Class B/C 도달** | 샌드박스 밖에서 스키마·인증·과금·대외 계약에 닿음 → 사람 |
| **경계 이탈 요구** | 실데이터·실사용자·실결제가 필요해짐(지침 28 §3) → 사람 |
| **되돌리기 어려운 행동** | 배포·발송·삭제·과금 → 동기 승인(지침 07 §5.5) |
| **QA 연속 실패** | 서로 다른 항목에서 연속 2회 QA 실패 = 기획이 틀렸다는 신호 → 재기획 |
| **자원 임계** | 착수 전 선언한 디스크·메모리 여유 하한 도달 (예: 디스크 30GB·메모리 25%) — 정리 스크립트로 버티지 말고 멈춘다 (§5b) |
| **기획 소진** | 남은 항목 0 → **시간이 남아도 끝낸다.** 남는 시간을 채우려 새 작업을 지어내지 않는다 |

> 마지막 항목이 핵심이다. 요구사항 "시간을 다 채울 필요 없음"은 여기서 규칙이 된다 — **일이 끝나면 끝난 것이다.** 시간을 메우려고 만든 작업은 거의 항상 가치가 음수다.

## 5b. 자원·정리 안전장치 (METH-149)

실사고(ai-icons 4건 340분): 장시간 루프 중 디스크 가득(ENOSPC) 180분 · 공간을 내려던 **정리 스크립트가 원고가 참조하던 렌더와 한글 폰트까지 삭제** 100분 · 메모리 포화로 시스템 정지 60분. 원인 추정: 다른 에이전트 도구가 저장소 안에 남기는 **숨은 상태**(턴 체크포인트 참조 `refs/codex` ~23GB + 버려진 객체 ~40GB). 디스크 정지 조건은 사고 당일 이후에야 생겼다.

1. **P0 기획에 자원 하한을 함께 선언**한다 — 디스크·메모리 여유, 주간 사용량 한도. 하한은 §5 정지 조건이다.
2. **정리·삭제 스크립트는 참조 검사 + 삭제 목록 보존**을 기본으로 한다 — 원고·산출물이 참조하는 경로는 건너뛰고, 지운 목록을 압축 보존해 복원 가능하게 한다(ai-icons `deleted-files.tsv.gz`). 기본은 미리 보기, `--apply` 를 줘야 지운다.
3. **고정 자원은 저장소 밖 고정 경로**로 둔다(폰트·런타임 — `ICONS_FONTS`·`ICONS_PYTHON` 류 환경변수). 정리 대상과 섞이지 않게.
4. **에이전트 도구의 숨은 상태를 주기 점검**한다 — `.git` 크기·`git for-each-ref` 의 낯선 네임스페이스(`refs/codex/*` 등)·도구 캐시 디렉터리. 루프 시작 시 한 번 재고, 증가 추세면 정리 계획부터 세운다.

## 6. 종료 보고 (stop report, 지침 07 §5.6 형식)

- **정지 사유**: 어느 조건이 발동했나 (기획 소진 / 예산 / no-progress / 게이트)
- **소비 vs 선언**: 예) 5/7 사이클 · 3/5 PR · 경과 4h20m / 선언 8h
- **검증 상태**: ground-truth 기준 — 테스트 N건 통과, 빌드 green, 렌더 확인 여부
- **완료한 것 / 남긴 것**: 남긴 것을 반드시 명시(침묵 절단 금지)
- **다음 선택지**: 재개하려면 무엇이 필요한가
- **resume handle**: 브랜치 · 기획 파일 경로 · checkpoint

## 7. 운영 형태 — 어떻게 실제로 돌리나

- **한 세션 연속 주행**: 사람이 자리를 비우고 AI가 §4 루프를 계속 돈다. 사이클마다 checkpoint 갱신(컴팩션 대비). 가장 단순하고 이 지침의 기본형.
- **자기 페이싱 루프**: 외부 대기(CI·배포·긴 빌드)가 끼는 작업이면 대기 구간에서 스스로 깨어나는 루프 형태로 돈다. 대기 시간을 사이클 수 계산에서 뺀다.
- **팬아웃 사이클**: 독립 항목이 여러 개면 한 사이클 안에서 병렬 처리(지침 08). 단 **검토·QA는 항목별로 독립**이어야 한다 — 한 판정기가 전부를 통과시키면 §4-2의 '통과는 약하다' 문제가 그대로 커진다.

> 어떤 형태든 **기획 파일과 checkpoint는 항상 갱신한다.** 자율주행의 산출물은 코드만이 아니라 "무엇을 왜 했고 무엇이 남았는가"의 기록이다.

## 8. 다른 지침과의 경계

- **지침 07 (예산·정지)**: 상위 규칙. 이 지침은 그 예산을 *사이클로 환산해 돌리는 법*.
- **지침 28 (실험 모드)**: 선결 조건. 샌드박스 밖 자율주행은 Class 게이트에서 반복 정지한다.
- **지침 06 (컴팩션)**: 8시간이면 반드시 발생 — 사이클 로그와 기획 파일이 생존 앵커.
- **지침 08 (서브에이전트)**: 팬아웃 사이클의 실행 규칙.
- **지침 23 (검증 규범)**: §4-3 QA의 판정 기준은 전부 여기서 온다. 판정 수단의 모범 — **사전 등록 실험 + 통계 결정**(α·신뢰 하한을 미리 정하고 «채택 안 함»도 기록, ai-icons 루프134·135 README).

## 9. 무인 예약 작업 — cron형 실행의 계약 (METH-149)

이 지침의 본문은 *사람이 자리를 비운 한 세션*이다. 주기 예약 작업(스케줄러가 매주 깨우는 세션·클라우드 루틴)은 **사람이 아예 없다** — 권한 프롬프트 하나에서 멈춰도 아무도 모른다. 실사고: 주간 등록부 갱신이 3주 연속 첫 명령의 권한 승인 대기에서 끊겼는데 «성공»으로 기록, 등록부 3주 미갱신·재채점 12일 정지(gamblescan 155분). 같은 repo 에서 예약 작업의 cwd 인 메인 체크아웃이 origin 보다 18커밋 뒤처진 채 다음 실행을 기다렸다.

1. **명령은 글자 그대로, 허용 규칙은 정확 일치로** 미리 등록한다 — 실행 중 새 권한이 필요하면 그 자체가 실패다. 실패 시 **우회 금지**(다른 명령으로 바꿔 «성공»시키지 않는다).
2. **보고 맨 위에 실패 단계**를 쓴다 — «완료»가 아니라 «어느 단계까지 갔나». 단계별 소요(`stepMs`)를 남겨 한도 접근을 본다(gamblescan KOL-021: 300초 한도).
3. **작업 디렉터리를 먼저 동기화**한다 — 첫 단계가 `git fetch` + fast-forward(실패하면 정지). 오래된 체크아웃 위에서 도는 예약 작업은 옛 코드로 운영 데이터를 쓴다.
4. **heartbeat — 안 돈 것을 잡는 장치를 따로 둔다.** 성공 보고는 «돈 경우»만 다룬다. 결과물의 신선도(마지막 적재 일자)를 다른 경로(대시보드·주간 점검·별도 감시)가 본다(지침 23 §1-8).
5. 원형: gamblescan `~/.claude/scheduled-tasks/*/SKILL.md` + `SOP_license-registry-refresh.md` §주기.
