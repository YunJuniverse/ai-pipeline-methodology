# 22_IR_사업기획_덱_제작_지침

> **출처**: `icons-invest` IR 덱 v1→v4 제작 회고를 방법론으로 환류. 웹리서치 3병렬(AI PPT 방법론·슬라이드 디자인 문법·2025~26 트렌드) + 실전 python-pptx 빌드 시스템(43장) + 멀티에이전트 실사 패널 + 100여 개 관찰/마찰 로그가 이 문서로 수렴한다. 흩어진 리서치 스냅샷이 아니라 *다음 덱을 바로 시작할 수 있는* 실행 플레이북.

## 1. 문서 개요

### 1.1 문서명
IR·사업기획 덱 제작 지침 (Deck as Code — 코드 빌드 + 렌더 검증 파이프라인)

### 1.2 문서 목적
IR/피치덱/사업기획 발표자료를 **코드로 빌드하고 렌더로 검증하는 파이프라인**으로 제작해 실사(due-diligence)를 견디는 완성도에 도달시키는 조직 표준. "덱을 한 번에 그려내는 AI 툴"에 의존하지 않고, 디자인을 *기계가 읽는 계약*으로 고정한 뒤 콘텐츠만 주입하고, 렌더 스크린샷·다관점 패널로 폐쇄 검증한다.

### 1.3 문서의 역할
지침 17(평가·가드레일) **§4.2 Guardrails-by-Construction**과 지침 20(프론트엔드 디자인 토큰)의 *시각 품질 가드레일*을 **슬라이드 산출물 레이어**에 인스턴스화한다. 20이 웹 UI의 색을 토큰으로 강제한다면, 본 문서는 덱의 색·타입·강조를 토큰으로 강제하고 *논증 정합·정직성*까지 검증 게이트로 강제한다. 콘텐츠 원본은 지침 10(사업기획서)이 소유하고, 본 문서는 *그 원본을 덱으로 변환하는 공정*만 다룬다(중복 금지).

### 1.4 적용 범위
IR 덱·피치덱·사업기획 발표자료·투자유치/제출용 리딩덱. 스택 기준은 `python-pptx` + LibreOffice(`soffice`) 렌더지만, §2·§4의 *원칙*(디자인 계약·검증 게이트·정직성 규율)은 스택 무관(Marp/Slidev/reveal 이식 가능). planning-only 트랙에서도 산출물이 덱이면 적용.

### 1.5 예상 독자
덱을 생성·수정하는 AI 모델, 덱을 검토·승인하는 사람, IR/기획 인계자.

### 1.6 관련 문서
- 지침 10 사업기획서 — 덱의 콘텐츠 원본(시장·BM·재무·로드맵). 본 문서는 *변환 공정*
- 지침 05 산출물 채널 분리 규칙 — 덱(외부 배포물)에 작업 메타 어휘 침투 금지(§5의 뿌리)
- 지침 17 평가·가드레일 — §4.2 Guardrails-by-Construction(상위 원칙)
- 지침 20 프론트엔드 디자인 토큰 — 자매 가드레일(웹 UI 시각 품질). 본 문서는 *덱 시각 품질*
- 스타터: `50_resources/skeletons/ir-deck-build/`

## 2. 핵심 원칙 — Deck as Code, 5단계 파이프라인

> **덱은 한 번에 그려지지 않는다. 소스를 정본화하고, 아웃라인을 승인받고, 디자인을 계약으로 고정하고, 코드로 주입하고, 렌더로 검증한다.** 2025~26 학계 수렴점(PPTAgent·AutoPresent·SlideGen·AeSlides)이 모두 이 4~5단계로 수렴했고, Gamma 류 상용툴은 PPTX 내보내기에서 대부분 수동보정이 필요해 브랜드 정밀 제어에 실패한다.

| 단계 | 핵심 산출물 | 게이트(넘어가는 조건) |
|---|---|---|
| **P0 소스 정본화(SSOT)** | 재무 xlsx·계획안·차트데이터를 "정본 1개"로 고정, 구버전은 `_archive/` | **정본 판정 기록** + **흡수 대상 원자료 전수 목록 확정** — 빌드 후 역방향 흡수(완성 덱에 자료를 나중에 끼워넣는 재작업)를 방지 |
| **P1 아웃라인/텍스트본 게이트** | 슬라이드별 `[헤드라인]+[본문]+[에셋]` 텍스트본(md/docx) | **사람 승인** — 논증 순서·장수 확정. 여기서 [헤드라인]만 이어읽어 논증 성립(타이틀 테스트) |
| **P2 디자인 계약 고정** | 빌드 스크립트 상단 토큰 블록(색 3단계·타입 6단계·마진·카드) | "콘텐츠는 이 아래를 수정 금지" 주석 계약 |
| **P3 코드 주입(원자적)** | `python-pptx`: 슬라이드 1개 = 함수 1개, 차트는 xlsx→PNG 자동재생성 | 전체 재생성 금지 — 패치 단위 수정만. **모든 패치 후 리드백 필수**(pdftotext·셰이프 스캔) — 재배열 실패가 구버전으로 *조용히 성공*한다 |
| **P4 렌더-검증 루프** | `soffice` 렌더 → 스크린샷 자기검토 + 멀티에이전트 실사 패널 | §4 검증 게이트 4종 + 실사 패널 통과 |
| **P5 파생물** | 송부용 요약본·재구성용 텍스트본·PDF 동기화 | 리딩덱 ↔ 발표덱 분리(§6) |

**불변 규율 5개:**
1. **P1 텍스트본이 아웃라인 승인 게이트다.** 텍스트본 없이 슬라이드를 그리기 시작하지 않는다.
2. **P2 디자인 계약은 스크립트 상단 한 곳에서만 정의되고, 슬라이드 코드는 토큰만 부른다.** 슬라이드 함수 안에 raw hex/pt를 쓰지 않는다(지침 20의 "이름=역할"을 덱에 인스턴스화).
3. **P3 슬라이드는 원자적으로 추가·수정한다.** 한 슬라이드 고치려고 덱 전체를 재생성하지 않는다(일관성·회귀 방지).
4. **텍스트본 *파일*이 유일 소스다 — 대화 합의본으로 빌드 금지.** 대화에서 합의한 내용과 파일이 다르면 *파일 우선*, 빌드 직전 해당 슬라이드 섹션을 파일에서 재확인한다(대화본 빌드 → 사용자 정정 실사고).
5. **슬라이드는 안정 ID로 참조하고 번호는 렌더 시 계산한다.** 장 삽입/삭제 1회마다 텍스트본·크로스레퍼런스·출처 위치·칩 매핑 4종 리매핑이 연쇄된다(43장 덱에서 재번호 8회+) — 순번을 키로 쓰지 않는다.

## 3. 디자인 계약 (기계가 읽는 토큰)

빌드 스크립트 상단에 고정하는 계약. `icons-invest` v4 정본 값을 기본값으로 제시하되, **바꾸는 것은 값(브랜드 색·서체)뿐, 구조(3단계·6단계·예산제)는 유지**한다.

### 3.1 색 토큰 — 3단계 위계 (더도 말고)
| 토큰 | 역할 | v4 값(다크 베이스 예시) |
|---|---|---|
| `TXT_HI` | 핵심 텍스트 | `WHITE` |
| `TXT_MID` | 본문 | `#D5DBF0` |
| `TXT_LOW` | 각주·라벨 (WCAG AA 4.5:1 검증) | `#9AA2C8` 이상 밝기 |

> **교훈**: v4 감사에서 라이트블루 7종 혼용이 "위계 아닌 잡음"으로 잡혔다. 유사색은 위계를 만들지 않는다 — 3단계로 퇴출.

### 3.2 타입 스케일 — 6단계 (28단계 금지)
`헤드라인 26 / 카드·섹션 14 / 소제목 12 / 본문 10.5 / 캡션 9.5 / 각주 9` (표지·클로징 디스플레이 크기는 예외).

> **교훈**: v4는 폰트가 28단계(7~104pt)로 난립했다. 배포덱 하한은 라벨 12pt(Superchart) — 7~8.5pt 39곳을 전량 승격. 타입 스케일 부재 = 위계 붕괴.

### 3.3 강조색 예산제 — 1색, 장당 1~2포인트
강조색(예: 코랄) 1개만. 장당 강조 1~2포인트 + 시스템 요소(키커·헤드라인 전절)로 제한. 초과분은 화이트/그레이로 강등.

> **교훈**: v4는 강조색이 202회(헤드라인·칩·뱃지·수치·화살표·밴드 동시) 남용돼 "신호 희석"으로 잡혔다. 강조는 희소해야 신호다(Mayer signaling).

### 3.4 헤드라인 = 완결 주장문 (Assertion-Evidence)
제목은 명사구가 아니라 **1~2줄 완결 문장 주장**, 본문은 불릿 대신 시각 증거. (예: "아이콘스의 4가지 기회"(X) → "…" 메시지형(O)). 통제 실험에서 이해·회상 유의 향상(Alley, Penn State).

### 3.5 레이아웃·서체·차트
- **벤토 그리드**: 이질적 정보(차트+인용+사진)를 모듈 카드로. 2026 트렌드 1순위이자 v4 카드 레이아웃의 정식화.
- **다크 프리미엄 베이스** + 강조 1색(테크·비즈니스 기본값).
- **서체**: 국내 표준 `Pretendard`(9굵기·SIL OFL). 렌더 환경에 설치 후 `pdffonts`로 임베드 검증(미설치 시 폴백으로 깨짐).
- **차트**: 그레이 기조 + 강조 1색(메시지 시리즈만), 범례 대신 **직접 라벨**(색약 접근성 겸, Knaflic), 본편 라벨은 정수 반올림(정밀값은 Appendix 표). 스택막대는 비교 대상 세그먼트를 바닥에, 이중축 회피(Datawrapper).

## 4. 검증 게이트 (P4) — 4종 + 실사 패널

### 4.1 슬라이드별 4종 테스트 (렌더 후)
1. **타이틀 테스트** — 헤드라인만 위→아래로 이어읽어 전체 논증 성립 (맥킨지/Minto)
2. **3초 글랜스** — 빌보드처럼 3초 안에 요지 파악 (Duarte). 스크린샷으로 확인
3. **Obvious 테스트** — 맥락 모르는 제3자가 이해 (YC, Kevin Hale)
4. **출처 정합** — 각주 수치가 P0 정본과 일치, citation 버전 일치

### 4.2 멀티에이전트 실사 패널 (이 방법론의 킬러 피처)
덱 PDF를 **4개 렌즈**가 각자 통독하고 결함을 지지 패널 수로 랭킹:
- ① **VC 심사역** — 투자 논리 사슬(시장→가격까지 균형)
- ② **실사 애널리스트** — 수치 정합성·방어력 점수
- ③ **내러티브 전문가** — 흐름·이음새·중복
- ④ **악마의 변호인** — 반박 시뮬레이션·자충돌 탐지

> **실증**: `icons-invest` v3.1 패널이 "2024 역성장 은폐 구조", "GMV=매출 계상 의혹", "왜 이 가격 0장", "내부 TODO 문구 인쇄" 등 실사 첫 미팅에서 부러질 치명결함 4건을 사전에 잡았다. 서브에이전트 오케스트레이션은 지침 08 참조(컨텍스트 격리 + 적대적 검증).

각 결함은 **자력 가능(🟢)/대표·재무 확인 필요(🔴)**로 분류해 액션 우선순위를 만든다.

**패널 결함 해소 루프 (필수)**: 패널이 지목한 치명 결함은 **TODO 항목으로 승격**하고, *다음 패널이 결함별 해소 여부를 명시 판정*한다 — 랭킹만 하고 끝내면 재발한다(실측: 1차 치명 5건 중 2차 패널까지 구조적 해소 2건뿐, 3건이 5일간 관통). 미해소 결함을 안고 다음 라운드를 진행하는 것은 게이트 위반이다.

## 5. 정직성·거버넌스 규율 (IR 특화)

IR 덱에만 있는, 실사를 견디게 하는 규율. 대부분 §05 산출물 채널 분리의 인스턴스다.

- **헤드라인 정직성**: "각주는 정직한데 헤드라인이 정직하지 않은 덱"은 실사 방어력이 무너진다. 역성장·GMV/인식매출 분리 같은 약점은 숨기지 말고 **정면돌파 1장**으로. "숨기면 잡히고 먼저 말하면 스토리".
- **내부 메타 어휘 차단**: "대표 확정 필요"·"감사 전"·"확정 필요" 같은 워크플로우 어휘가 대외비 덱에 인쇄되면 "숫자 안 닫힌 회사"로 기록된다 → 외부 독자형으로 치환("2026.7 기준"·"세부 조건 협의 중"). 단 데모·목업·계획치의 정직성 표기는 유지.
- **정본 수치 일원화**: 부문 split·손익 정본을 P0에서 못 박고 덱 전역에 동일 기준. headline 수치와 차트가 상충하면 실사 즉사(예: 헤드라인 "본업 1,530억" vs 차트 "통합 1,894억").
- **민감도 등급**: 실명 이력·실 재무 포함 덱은 '제한' — 외부공유·`export`·공개 URL 게재 시 **사용자 확인 필수**(무단 배포 금지).
- **Class 판정**: 밸류에이션·투자조건·공개 배포 결정은 자동 **Class C**(대표/법률 스코프). AI는 틀·문구만 개선하고 수치는 확인 대기.

## 6. 리딩덱 vs 발표덱 (P5 파생)

- **두 벌 분리가 글로벌 표준**: 송부용 **리딩덱**(텍스트 자립·단독 열람 가능) + 발표용(텍스트 최소). 한 벌로 둘 다 하면 양쪽 실패.
- 무게중심은 **리딩덱** — 투자 판단은 투자자가 혼자 PDF 넘기는 순간에 발생(DocSend 열람 실측 ~2분). 국내 관례(종합형 IR 20~30장 먼저, 발표덱 파생)와 합치.
- **분량 예산**: 리딩덱 20~30장, 앞부분(시장) 과부하 금지, 상세 표/전표는 Appendix로 분리. 재무 슬라이드는 빼지 말고 **요약형**(차트+핵심지표 3~5개+헤드라인), 상세는 Appendix.
- **파생물 자동화**: 요약본은 본편 리빌드 후 재실행하는 생성기로(본편이 정본, 요약본은 파생). PDF는 pptx 빌드 시 동시 생성·동기화.

## 7. 반복 함정 체크리스트 (마찰 로그 박제)

빌드 체크에 넣을 것:

- [ ] **하단 겹침**: 하단 요소 `y+h ≤ 7.05`(인치) 수치 검산 — 렌더 육안만으론 놓친다(footer 위 침범).
- [ ] **에셋 유실**: 채팅에 붙인 이미지는 파일로 안 남는다 → 에셋은 처음부터 `~/Downloads` 저장 요청.
- [ ] **재무 xlsx 수치가 텍스트로 저장**: 합계·차트가 깨진다 → 숫자 강제변환 후 사용.
- [ ] **레거시 pptx 이미지 매칭**: 텍스트만으론 어떤 이미지인지 모른다 → 콘택트시트 3분할 시각 판독.
- [ ] **서체 미임베드**: 렌더 환경에 서체 없으면 폴백으로 깨진다 → `pdffonts`로 임베드 확인.
- [ ] **목차 정본**: 기본 목차가 척추. 제출 변형(정부지원·IR용)은 *마지막에 재배열만*.
- [ ] **인코딩**: 공공 데이터(DART 등) `utf-8→euc-kr→cp949` 폴백.
- [ ] **중복 미관리**: 같은 수치·사례가 3회+ 반복되면 파이프라인 부풀리기 시그널로 읽힌다 → 클라이맥스 1곳만.
- [ ] **빌드 무증상 실패**: 블록 재배열이 실패해도 빌드는 구버전으로 조용히 성공 → 패치마다 리드백(pdftotext/셰이프 스캔)으로 반영 확인.
- [ ] **차트 PNG 글리프**: PIL 차트는 서체 임베드 검증(pdffonts) 밖 — 서체에 없는 문자(한자 등)는 tofu로 렌더 → 라벨 문자셋을 한글/영문/숫자로 제한 + 200dpi 줌 검증.
- [ ] **검산 범위**: geometry 검산은 *전 셰이프*(풀블리드 배경 제외) 대상 — 그림 셰이프를 빼면 이미지 오버플로를 놓친다.
- [ ] **감사 스크립트 페이지 인덱스 하드코딩 금지**: 장 번호↔PDF 페이지를 하드코딩하면 재번호마다 오탐 — 헤드라인 문자열로 페이지를 식별한 뒤 수치 검사.
- [ ] **extracted 에셋 문맥 소실**: `media/` 순번만으로는 슬라이드 귀속을 모른다(오귀속 실사고) → python-pptx로 해당 슬라이드 shape blob 직접 추출.
- [ ] **외부 이미지 소싱 2단 검증**: 검색 1차 결과는 무관 이미지 매칭 위험 → 제목 키워드 필터 + 다운로드 후 시각 확인. CC 크레딧은 누적 관리.
- [ ] **대용량 처리 백그라운드**: 100MB+/수백 페이지 PDF 추출은 Bash 타임아웃 초과 → 처음부터 백그라운드 실행.

## 7b. 기계 게이트·차트 계층 (v3, METH-129 — 2026 리서치 접목)

> 학계 검증: 코드 기반 생성이 원클릭 생성보다 우위(AutoPresent, CVPR 2025), 디자인 계약 선확정이 동일 구조로 실증(Design-First 2026) — 본 지침의 접근 유지 근거. 접목분:

- **결정론적 레이아웃 린트 4종** (P4 렌더 검증 *앞단*, VLM 불필요 — 도형 좌표 연산): ① 요소 충돌·경계 침범 ② 과잉 여백(국소 분산) ③ 무게중심 불균형 ④ 종횡비 왜곡. build 체크에 fail-closed로 편입(AeSlides 4메트릭).
- **실사 패널 taxonomy 주입**: §4.2 패널 프롬프트에 결함 분류체계+이진 체크리스트 루브릭을 주입한다 — 자유 평가 대비 탐지·수정 모두 우위 실증(SlideAudit, UIST 2025).
- **차트는 선언 계층**: 데이터→차트는 LLM이 Vega-Lite류 선언 스펙을 생성하고 결정론적 렌더러가 PNG를 만들어 주입한다. **차트 수치 검증을 VLM에 맡기지 않는다**(큰 자릿수 오독 실증) — 스펙↔데이터 대조로.
- **리플렉션 루프**: P4를 "렌더→관찰→수정" 반복으로 승격하되 반복 예산 상한 선언(지침 07 합류).
- **경계 2종**: ① 최종 산출물이 편집 가능 .pptx인 작업에서 HTML→PPTX 변환을 주 경로로 금지(상용 원클릭 충실도 붕괴의 공통 원인 — PresentBench 최고 70.8/100) ② 상용 덱 API는 초안 소재까지만(Tome 폐업 — 벤더 종료 시 산출물 접근 소멸).

## 8. Day-1 적용 체크리스트 (새 덱 시작)

## 9. 안티패턴·교훈 (정직 모드)

- **"AI 한 방 생성"** — 상용툴 원클릭 덱은 IR급에서 수동보정 지옥. 파이프라인이 이긴다.
- **디자인을 슬라이드마다 즉흥 결정** — raw hex/pt가 슬라이드에 흩어지면 리브랜딩·일관성 마비. 계약 상단 고정.
- **약점 은폐** — 합산 5분이면 드러나는 역성장·GMV를 숨기면 실사 방어력 붕괴. 정면돌파가 스토리.
- **리딩덱=발표덱 한 벌** — 텍스트 최소 발표덱을 송부하면 자립 열람 실패, 텍스트 과다 덱을 발표하면 글랜스 실패.
- **출처 없는 자신감** — 확인 불가 통계(설문·비율 공식)를 헤드라인에 쓰면 실사 반박. 각주 규율 + 인용 금지 목록 유지.
