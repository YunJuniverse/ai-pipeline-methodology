# 24. 착수 게이트 — 정본·전제·해석 확인

> 일을 *시작하기 전에* 확인해야 하는 4가지. 2026-07 전 레포 월간 전수조사에서 **정본·전제 미확인(P5, 5개 repo)**이
> 최고 단일 비용군(ai-icons 195분 축 전면 반전·gamblescan 90분+80분·invest-ops 딜 메모 전면 재계산)으로 실증되어 신설(METH-124).
> 핵심 가치: **비싼 실수는 실행이 아니라 착수에서 만들어진다. 확인 질문 1개가 재작업 1일을 산다.**

---

## 1. 정본(SoT) 확인 — "무엇이 사실의 기준인가"를 사용자에게 묻는다

실사고: 하이웍스 조직도를 정본으로 *단정*하고 13개 티켓에 걸쳐 자기신고 데이터를 덮어씀 → 실제 정본은 반대 → 전면 역방향 재작업(ai-icons, 최대 단일 손실).

- **과거 사실을 기록하는 산출물**(RCM·장부·이력·실사)은 착수 전에 "무엇이 정본인가"를 사용자에게 확인한다 — 소스가 2개 이상이면 단정 금지.
- 정본과 실제가 다른 예외는 코드 주석·문서에 박제하고 이동 이력과 분리한다(재파싱 때 자동 복귀 방지).
- 기준 축을 바꾸면 그 축으로 계산하던 파생 지표를 전수 재해석한다 — 숫자는 맞는데 뜻이 없는 상태를 방지.
- 원자료 반입 즉시 당사자·소유관계·수신 성격을 확인한다(invest-ops: 미확인 프레이밍 위에서 1차 분석 전체가 무효).

## 2. 조사·문서의 진단은 착수 시점에 코드로 재확인한다

실사고: 조사 스냅샷의 "데이터원이 이미 존재, 호출만 하면 됨"·"아무것도 차감 안 됨" 진단이 둘 다 오진 — 그대로 착수했으면 오답 구현(gamblescan 2회 80분, repeat_of 연쇄).

- 스냅샷·인계 문서·이전 세션의 *진단*은 착수 시점에 실제 코드·데이터로 재검증한다. 문서는 낡는다 — 특히 "이미 있다/없다" 류 존재 판정.
- 증상 진단은 **확증 증거가 아니라 반증 대조군**으로 확인한다 — 가설에 맞는 증거 수집이 아니라 "정상이라면 이래야 한다"의 대조 실험(오진 2회를 코드 작성 전에 차단한 실례).
- 집계·라벨을 믿지 말고 산출 코드를 역추적한다("작성 인원 64"가 사람 수가 아니었음). **부재와 미포착은 다르다** — 회수 못 한 영역은 '없음'이 아니라 '불명'.

## 3. 해석 계약 — 요청·시안의 해석을 첫 질문으로 고정한다

실사고: 시안을 "취사선택 참고안"으로 해석 → 오너 의도는 "정확 구현" → 전 항목 재대조(talmo 25분+별도 세션). "구조 텍스트는 코드 유지"로 좁게 그은 범위가 PM 의도와 어긋나 PR 재작업(tshome).

- **디자인 산출물 인계 시**: "정확 구현인가, 참고안인가"를 첫 질문으로. 
- **"관리 쉽게·개선해줘" 류 모호 요청**: 범위(어디까지)를 처음에 명시적으로 질의 — 좁게 긋고 재작업하는 것보다 싸다.
- **요청의 표면 진단을 코드로 반증한다**: "IR 관리가 어렵다" → 실제 갭은 딴 곳(이미 CMS 설계, 문제는 편집 주체). 요청 문면대로 착수하면 오답이 된다.
- 결정 질문을 던지기 전에 "어떤 답이 다른 질문의 전제를 깨는가"를 점검한다(선택지 전제 붕괴로 재수렴).

## 4. 사용자가 그은 경계는 거절 전에 원문으로 검증한다

실사고: 사용자의 "평점 말고 공개된 사실만" 구분을 검증 없이 2회 거절 → robots.txt를 끝까지 읽으니 거절 근거가 부정확 → 그 사이 대안 작업이 90분 손실 + 덮어쓰기 사고(gamblescan, 단일 최대).

- 사용자가 스스로 경계·근거를 제시하면(이건 되고 저건 안 된다), 거절하기 전에 **1차 출처를 직접 열어 확인**한다. 검색 요약·기억은 뉘앙스를 뭉갠다.
- 판정을 표에 ❌로 적기 전에 공식 사이트·원문을 직접 연다(오픈뱅킹 "개인 불가" 오판 실례).
- 확인하지 않은 플랫폼 동작을 단정해 안내하지 않는다(GitHub base 리타깃 오안내 → 사용자가 안내대로 했는데 사고).

## 5. 착수 전 체크 (요약)

작업 유형별로 해당 항목만 — 전 항목 기계 적용이 아니라 *비싼 실수의 길목*만 지킨다:

| 상황 | 착수 전 질문 |
|---|---|
| 과거 사실 기록물·다중 소스 | 무엇이 정본인가? (사용자 확인) |
| 문서·스냅샷 기반 착수 | 그 진단, 지금도 코드에서 참인가? |
| 시안·디자인 인계 | 정확 구현인가 참고안인가? |
| 모호 요청("쉽게·개선") | 범위는 어디까지인가? |
| 사용자 경계 제시 | 원문 확인했는가? (거절 전 필수) |
| 증상 디버깅 | 반증 대조군은 무엇인가? |
