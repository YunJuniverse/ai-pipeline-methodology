# 23. 검증 규범

> "검증했다"가 실제로 무엇을 보증해야 하는가의 규칙. 2026-07 전 레포 월간 전수조사(11개 repo·마찰 302건)에서
> **무음 실패(P4, 6개 repo)·빈 상태 검증(P9, 5개 repo)·검증불가 방치(P12, 4개 repo)**가 반복 손실원으로 실증되어 신설(METH-123).
> 핵심 가치: **성공처럼 보이는 실패를 성공으로 세지 않는다. 검증 못 한 것을 됐다고 말하지 않는다.**

---

## 1. 무음 실패 프로토콜 — "성공처럼 보이는 실패"를 잡는 4규칙

실사고 계보: `.catch(()=>[])`가 수익 표면 소등 은폐(gamblescan)·Vercel 한도 무음 스킵·zsh 루프 오작동·빈 스크린샷(talmo)·키 오매칭 무에러 null(ai-icons 40분)·빌드 실패해도 구버전으로 조용히 성공(icons-invest).

1. **0건 처리 = 실패.** 일괄 처리·수집·변환 스크립트는 "N건 처리"의 N이 0이거나 기대 하한 미달이면 실패로 종료한다(sanity assert). "에러 없음"은 "작동함"이 아니다.
2. **검사 못 함 ≠ 깨끗함.** 검사기가 대상 파일을 0개 찾으면 통과가 아니라 exit 1이다 — 가드가 헛도는 상태와 실제로 깨끗한 상태를 구분한다.
3. **금지형 가드는 negative case로 실효를 증명한다.** 가드 신설 시 위반을 일부러 주입 → 정확히 그 지점을 지목하며 실패하는지 확인 → git diff로 원복 검증. 통과만 하는 가드는 아무것도 보증하지 않는다.
4. **빌드 통과 ≠ 산출물 정상.** 패치 후에는 산출물을 리드백한다 — 프로덕션 빌드 CSS grep(Lightning CSS가 미참조 변수를 제거), pdftotext/셰이프 스캔(pptx 재배열 실패가 구버전으로 조용히 성공), 배포 후 실서빙 확인(배포 한도 무음 스킵). 에러 삼킴(`.catch`·`|| true`·`2>/dev/null`)은 실패를 침묵시키는 결합이다 — 삼킬 때는 반드시 대체 신호(로그·카운트)를 남긴다.

## 2. 상태 아닌 내용으로 검증한다 — UI·산출물 검증 3기준

실사고 계보: 데이터 0건이라 차트 파손 은폐(icons-marketing)·DOM 존재만 확인해 클리핑 버그 배포·URL만 믿어 404 스크린샷 채택(icons)·카드 크기 검수로 브랜드 라벨 놓침 75분(talmo)·RSC 스트리밍이라 HTML grep 거짓 음성(gamblescan)·가로 스크롤은 scrollWidth 실측으로만 검출(lifeManager).

1. **비어있지 않은 데이터로.** 빈 상태로만 검증한 화면·차트·목록은 검증되지 않은 것이다. 실물 규모에 가까운 데이터를 넣고 본다(스케일 의존 상수 — limit·임계값·풀 크기 — 는 데이터 N배 확장 시 전수 재검토).
2. **최대 표시 크기로.** 이미지·시각 자산 검수는 실제 최대 표시 크기 기준(썸네일 검수로는 히어로 결함을 못 본다). 반응형은 넘침 + 줄나눔 품질 + `scrollWidth` 실측까지.
3. **존재가 아니라 내용·가시성으로.** "200이 뜬다·DOM에 있다·URL이 맞다"가 아니라 **기대한 내용이 실제로 보이는가** — 제목 텍스트 어서션, `elementFromPoint`/스크린샷 가시성, 스트리밍 SSR은 HTML grep 대신 페이로드 구조 또는 브라우저. 성능 검증은 "좋아졌다"가 아니라 **"예측한 곳에서 예측한 만큼"**(가설-일치 확인).

리팩터·마이그레이션 추가 규칙: **"결과 동일" 확인은 배선을 증명하지 않는다** — 소스를 일부러 바꿔 결과가 따라 바뀌는지 역방향 테스트. ID 재매핑은 "키로 조회하는 전 지점"을 명시 목록화(키 불일치는 에러 없이 null).

## 3. 검증불가 등록부 — 못 한 것을 됐다고 말하지 않는다

실사고 계보: 드래그·업로드·인증 UI를 브라우저 자동화로 검증 불가, 우회를 매번 재발명(lifeManager 6건 93분)·자격증명 필요 단계는 승인받아도 AI가 수행 불가(tshome).

1. **검증 못 한 항목은 명시적으로 등록한다** — 산출물·PR·checkpoint에 4필드로: *무엇을 / 왜 못 했나 / 대체 검증(한 것) / 확인 요청 대상(사람·실기기)*. "미검증 상태로 머지"는 가능하되 침묵은 금지.
2. **표준 우회 사다리** (재발명 금지): ① 데이터 직접 주입(execute_sql·시드) ② JS 직접 호출(`form.requestSubmit` 등) ③ 단위테스트로 쓰기 경로 커버 ④ 사람·실기기 확인 요청. 자격증명·결제·CAPTCHA는 처음부터 ④ — AI 불가 영역.
3. **비-포인터 대안 동반 구현**: 드래그·업로드류 UI는 탭/버튼 대안을 함께 만든다 — 미검증 상태로도 사용자가 막히지 않고, 대안 경로가 검증 가능 경로가 된다.
