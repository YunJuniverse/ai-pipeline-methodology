# SOP: repo 밖 스프레드시트 정본 편집 (METH-149)

> **상시 브리프** — Google Sheet 같은 repo 밖 정본을 브라우저로 고칠 때의 절차. 상류 공통 SOP(전 repo 배포).
> 근거: 2026-11 전수조사 — drip-chat-planning 12건 155분(마찰의 53%)·lifeManager 6건 95분. 브라우저 입력은 **오류 없이** 값을 잃는다.

## 트리거
- **인식 신호**: "시트에 반영해줘", "구글 시트 고쳐줘", "정본 시트 업데이트", 시트·폼·게시 덱 링크와 함께 수정 요청
- **주기 / 이벤트**: 기획 결정이 바뀐 직후 · 회의 결과 반영 · repo 문서 갱신과 함께 시트 동기화

## 입력
- 정본 링크와 대상 탭·범위(«시트»가 파일인지 탭인지 먼저 확정 — lifeManager 용어 모호 재작업)
- 바꿀 칸 목록(주소·전 값·새 값) — **의도한 칸 수**를 미리 센다
- 편집 커넥터가 있으면 브라우저 UI 대신 그것을 쓴다(API·MCP). 아래는 UI 경로

## 절차
1. **최신 확인** — 파일 수정 시각(Drive `modifiedTime`·버전 기록)을 본다. 마지막으로 읽은 뒤 바뀌었으면 다시 읽는다(동시 편집으로 행이 밀려 30여 칸 미반영 — drip-chat-planning).
2. **편집 전 사본 확보** — xlsx 로 내려받아 `before.xlsx` 로 둔다(스크래치가 아니라 작업 폴더, 지침 30 §8b).
3. **칸 이동은 이름 상자로** — 이름 상자 클릭 → 주소 입력 → Enter → **잠깐 대기** → 셀 확인 후 입력. 포커스가 늦게 오면 A1·이름 상자에 값이 들어간다.
4. **한글 입력은 첫 글자 유실을 전제** — 셀 편집 모드 진입 후 입력하거나, 값 붙여넣기로 넣는다. 자동완성이 끼어들면 Esc 후 다시.
5. **서식 칸 주의** — `%` 서식 칸에 `25%` 를 치면 이중 서식이 될 수 있다. 숫자만 넣고 서식으로 표시.
6. **열·행 삽입은 규칙 복제를 확인** — 체크박스·조건부 서식·데이터 확인이 함께 복제된다. 삽입 뒤 새 열의 규칙을 지운다.
7. **편집 후 내려받아 diff** — `after.xlsx` 를 받아 `before` 와 셀 단위로 비교한다. **바뀐 칸 수 = 의도한 칸 수, 그 밖의 변경 0칸**이어야 끝이다(지침 23 §2-8). 다르면 그 칸만 다시 고치고 diff 를 반복.
8. **repo 쪽 기록** — 바뀐 칸 요약(주소·전후)과 기준 시각을 관련 문서·커밋에 남긴다. 인계물은 사본 파일이 아니라 정본 링크 + 기준 시각(지침 24 §1).

## 산출물 · 위치
- 정본 시트(갱신) · 작업 폴더의 before/after diff 요약 · repo 문서의 변경 요지

## 주의점 · 스코프 경계 · 자주 하는 실수
- `IMPORTRANGE` 액세스 허용·공유 권한 변경은 사람 클릭이 필요 — 요청하고 기다린다(검증불가 등록부, 지침 23 §3).
- 탭 이름 변경·열 덮어쓰기는 다른 시트의 참조를 깨뜨린다 — 참조 수식을 먼저 찾는다.
- 사람이 시트를 직접 고친 흔적이 있으면 덮지 말고 그 위에 패치(지침 24 §1).
- 가안 값은 시트에도 상태 표기(`[가안]`)를 단다(지침 24 §3c).
