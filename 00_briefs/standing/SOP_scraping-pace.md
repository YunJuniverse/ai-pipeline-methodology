# SOP · 외부 소스 수집·스크래핑 페이스 (METH-125)

> 상시 SOP — 외부 사이트 크롤·대량 수집 착수 전 반드시 확인. gamblescan에서 4단 승급 재발(누적 190분)한
> 마찰 체인을 승급한 것(전수조사 P7, 6개 repo). 원 SOP: gamblescan `00_briefs/standing/SOP_scraping-pace.md`.

## 트리거
- 외부 사이트를 10페이지 이상 수집하려 할 때 · WebFetch가 403/차단될 때 · 크롤 속도가 떨어질 때.

## 핵심 사실 (실측 근거)
1. **크롤 페널티는 누적된다** — 같은 IP·같은 사이트 반복 크롤 시 배치 허용량이 계속 줄어든다(실측 1,451→1,200→949→311). 18시간 휴식으로 회복 안 됨.
2. **소표본 프로브 통과 ≠ 허용량 회복** — 프로브 몇 건이 정상이어도 본 배치는 수백 건에서 막힌다.
3. **IP 교체(VPN)는 해법이 아니다** — 데이터센터 대역은 오히려 더 엄격히 취급될 수 있다. 차단이 계속되면 IP를 또 바꾸지 말고 멈춘다.
4. **한 소스 남용이 다른 소스 접근성까지 파괴한다** — IP 평판 하락으로 무관한 사이트가 403이 된 실사례.
5. **소프트 스로틀은 실패 0인데 진행 0** — 로그 버퍼링에 속지 말고 진행 캐시/DB로 실제 페이스를 감시.

## 절차
1. **페이스**: 요청 간 최소 1.8초 + 차단 감지 백오프. 하루 1~2배치, 배치 캡 ≤800, 배치 간 최소 반나절.
2. **dry-run은 소량으로** — 전량 dry-run도 실크롤과 같은 부하다.
3. **멱등 재개 설계** — 부분 완료 후 정지·재개 가능하게(진행 캐시·이미 수집분 스킵).
4. **차단 시**: 정지 → 다른 소스·다른 시점 전략으로 전환. 브라우저 경로가 열려 있으면 그것 사용.
5. **소스 폴백 사다리** (리서치 공통): WebFetch → Firecrawl → 인앱 브라우저(실 컨텍스트) → **공개 API 탐색 우선**(SPA·ERP는 UI 스크래핑 전에 API 문서부터). robots.txt는 끝까지 읽고 판단.
6. **폴백 사용 시 산출물에 정밀도 한계를 표기**한다(예: "웹검색 요약 기준 — 정밀 시세 미확보").

## 신규 소스 채택 3축 평가 (착수 전)
- **열거 가능성**: 대상 전량을 나열할 수 있는가(사이트맵 인덱스는 하위까지 추적).
- **커버리지율**: 무작위 10~20페이지로 목표 필드 보유 비율 실측 → 그 비율로 기대 수확 계산(존재 확인 ≠ 커버리지).
- **모호성**: 페이지 단위뿐 아니라 필드 값 내부(한 셀 다중값)도 확인.

## 산출물
- 수집 스크립트에 페이스·백오프·멱등 재개 내장. 관찰 로그에 소스별 허용량·차단 이력 기록(`where` 통일 표기로 재발 집계).
