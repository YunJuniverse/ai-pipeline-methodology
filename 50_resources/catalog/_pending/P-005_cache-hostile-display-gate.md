## 패턴 (Pattern)

캐시 계층을 통제할 수 없는 호스팅 플랫폼(SaaS 스킨·CDN 강제 캐시)에서 시간 민감 UI(타임딜·마감 카운트다운·기간 한정 표시)를 정확히 보이려면, 문서를 믿지 말고 **클라이언트가 원본에 물어 스스로 고치게** 한다. 7항이 한 벌이다.

1. **원본 판정이 로컬 문서를 항상 덮어쓴다** — 로컬 마크업은 낡은 사본일 수 있다.
2. **첫 판정도 2/3 다수결로, 방향은 비대칭이 아니게** — 낡은 사본은 «켜짐»과 «꺼짐» 양쪽으로 거짓말한다.
3. **재검증 루프는 연속 2회 합의 + 탭 복귀 시 리셋.**
4. **예약(타이머)은 판정마다 재무장** — 원샷 가드는 첫 판정이 틀리면 영구히 틀린다.
5. **전환은 전부 가역 토글** — 되돌릴 수 없는 DOM 파괴 금지.
6. **마크업 재료가 없는 사본에는 원본 값으로 되살린다.**
7. **실패는 fail-open** — 표시 로직의 최악은 매출 차단이다.

## 근거 (Evidence)

**부정 판정만 합의를 요구하던 비대칭 규칙이 반나절 만에 역효과를 냈다** — 옛 기간 사본이 `run` 으로 복권되어 **시작 전 딜을 켰다**(cafe24-renewal). 방향 무관 다수결로 교체해 해소. 판정 오라클은 전용 프로브 표면에 두었다(지침 23 §4-5).

## 안티패턴 (Anti-Pattern)

- 한쪽 방향(끄기)만 엄격히 검증하고 반대 방향은 단독 신호로 수용.
- 서버 캐시를 고치려는 시도에 시간을 쓰기(플랫폼이 통제권을 안 준다).
- 판정 실패 시 fail-closed 로 상품을 숨김.

## 관련 자료

- 지침 23 §4-5(판정 오라클은 전용 표면) · §1-4(도구가 다르면 사본도 다르다).
- 플랫폼 고유 사실(Cafe24 캐시 4계층·모듈 동작)은 상류로 올리지 않는다 — 정본은 하류 repo 의 `20_constraints/`.

## 승급 조건

**다른 플랫폼**(타 SaaS·CDN 강제 캐시)에서 같은 자가치유 게이트 필요가 재현되면 active `C-NNN` 등재 후 스켈레톤 bake 검토. 현재는 1 repo 1회이므로 스켈레톤 신설 대상이 아니다(`skeletons/_README` — Pending 은 bake-in 불가).
