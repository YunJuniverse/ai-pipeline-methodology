## 0. 4개 도메인을 관통하는 공통 원칙 (교차 발견)

리서치 전 도메인에서 독립적으로 같은 구조가 수렴했다 — 이것이 "AI 디자인 공통 규범"의 뼈대다.

1. **벤더는 죽는다 — 모델 추상화.** 조사 중에만 소멸 3건: OpenAI Sora(2026-04 종료·API 9월 선셋), Tome(2025-04 종료), Galileo AI(Google 인수·단독 소멸). 파이프라인은 모델명이 아니라 *역할*(t2v/i2v/이미지/코드생성)로 정의하고 모델은 설정에서 교체.
2. **생성 전 정본(캐논) 확정.** 캐릭터 시트(이미지)·레퍼런스 캐논 3~5장(영상)·DESIGN.md 미학 헌장(웹)·디자인 계약/텍스트본(덱) — 전 도메인이 "정본 먼저, 생성 나중" 구조. 우리 지침 22 P0·24 착수 게이트와 동형.
3. **프롬프트·생성 이력 = 코드.** 프롬프트/시드/모델버전/레퍼런스를 git 버전 관리 + 장(클립)당 provenance 기록. **한국에서 이 기록이 곧 저작권 등록 증빙**(인간 창작 기여 입증 — 문체부 안내서 2025-06).
4. **2단 생성 + 선별이 본질.** 저가·저해상 1차 패스 → 통과분만 풀 퀄리티. 재시도 3회 상한(초과 = 프롬프트가 아니라 계획 재검토). 프로덕션 비용의 지배 항은 생성이 아니라 **선별**(코카콜라: 7만 클립→1편). 생성:채택 비율을 KPI로.
5. **사람 게이트 3위치 고정**: ① 방향·캐논 승인(착수) ② 풀 퀄리티 렌더 승인 ③ 퍼블리시 직전 브랜드 QA. 중간 생성 반복은 자율(우리 지침 07 예산 규칙과 합류).
6. **검증은 2층**: 1층 결정론적 기계 게이트(좌표·스펙 대조 — 싸고 재현 가능) + 2층 루브릭/taxonomy 주입 VLM·사람 심사(자유 평가보다 체크리스트 주입이 실증 우위). 우리 지침 23 검증 규범의 디자인 인스턴스.
7. **텍스트·로고는 모델에게 생성시키지 않는다.** 영상·이미지 공통 취약점 — 편집 단계 오버레이 또는 특화 도구(Ideogram류)로.
8. **AI 티(slop) 회피 = 금지 기본값 명시 + 레퍼런스 주입.** "무엇을 피할지 이름 붙여 금지"가 검증된 1급 기법(웹·이미지·영상 공통).
9. **법·컴플라이언스 게이트**: AI기본법 시행(2026-01-22) — 생성물 표시 의무(비가시 워터마크 허용, SynthID/C2PA 자동 부착 도구 유리). 순수 AI 산출물은 한·미 공통 저작권 등록 불가 → IP 비즈니스는 인간 기여 기록 필수. 무료 티어로 IP 에셋 제작 금지(소유권 함정). 타사 IP·워터마크 유사 출력은 수정 없이 폐기(Getty 판결: 출력 내 상표 = 침해). 유통 플랫폼 AI 정책 확인(네이버웹툰 공모전 AI 금지 등).

## 1. AI 영상 생성 (요지)

- **지형(2026-07)**: Kling 3.0(종합 1위, ~$0.10/s)·Veo 3.1(시네마틱·오디오 동기, $0.05~0.40/s) 양강. Seedance 2.0(오디오 조인트)·Wan 2.7(Apache 2.0 오픈소스)·Hailuo(가성비)·Pika(속도)·HeyGen(아바타). **Sora 소멸.**
- **파이프라인**: 사람 스크립트 → 샷리스트 락(4~8초 클립 분해) → 레퍼런스 캐논 제작 → 저가 1차 패스 → 풀 렌더(3회 상한) → 편집·합성 → 브랜드 QA.
- **일관성**: 레퍼런스 주입(Veo Ingredients ≤3장·Kling Elements ≤4장)이 시드보다 우위. First/Last Frame 체이닝. 프롬프트 5부 구조(촬영기법+피사체+행동+맥락+스타일), 오디오는 `SFX:`/따옴표/타임스탬프.
- **방법론화 후보 핵심**: 샷 스펙 파일(YAML: shot_id·duration·framing·camera·reference_assets·model·seed·prompt_version), 비용 공식 `Σ(초×단가×시도계수)` + 채택률로 계수 갱신, 배치 API -50%.

## 2. AI 이미지 생성 (요지)

- **에셋 관리**: `<프로젝트>_<에셋ID>_<용도>_<v#>_<상태>` 명명 + `approved/` 분리 + 장당 provenance. "final2.png" 안티패턴.

## 3. AI PPT 제작 (요지 — 지침 22 관점)

- **우리 접근의 외부 검증**: 코드 기반 생성 > end-to-end 이미지 생성(AutoPresent, CVPR 2025), 디자인 명세 선확정 후 구현(Design First Code Later, 2026-04) — Deck-as-Code와 동일 구조의 독립 발견. 상용 원클릭(Gamma 3.0 등)은 화면 품질은 올랐으나 **PPTX 왕복 충실도는 여전히 구조적 약점**(PresentBench 최고 70.8/100). 충실도 상위는 전부 네이티브 생성 진영(Copilot·Plus AI·Gemini in Slides).
- **접목 후보 (지침 22 v3 후보)**:
  1. **결정론적 레이아웃 린트 4종**(AeSlides): 요소 충돌·경계 침범·과잉 여백·무게중심 불균형 — VLM 없이 도형 좌표 연산, CI 게이트화.
  2. **실사 패널에 결함 분류체계(taxonomy) 주입**(SlideAudit, UIST 2025): 자유 평가보다 탐지·수정 모두 우위 실증.
  3. **차트는 선언 계층**: LLM이 Vega-Lite 스펙 생성 → 결정론 렌더러가 그림 → 수치 검증은 스펙-데이터 대조(VLM에 차트 숫자 읽기 금지 — CHI 2026: 큰 자릿수 오독).
  4. 렌더→관찰→수정 리플렉션 루프(반복 예산 상한과 함께 — DeepPresenter 방향).
  5. **경계**: HTML→PPTX 변환을 주 경로로 금지(Gamma·Manus류 충실도 붕괴 공통 원인), 상용 API는 초안 소재까지만(Tome 사망 교훈).

## 7. 방법 한계

- 에이전트 4기 각 1패스 — 교차 검증 없음. 가격은 서드파티 집계 다수 — 계약 전 공식 페이지 재확인.

- 상세 근거·출처 전체 목록은 각 도메인 에이전트 보고 원문(이 세션 트랜스크립트) — 본 스냅샷이 보존 요약본.
