## 3. observe-timeout-approved-fallback (gamblescan → tool/observe)

**제안**: observe(pre-push 경로)가 무한 블록하지 말고 결정적 타임아웃 + 사람 승인 폴백을 *기록*하도록. 근거: observe 반복 행 → 소유자가 제한적 no-verify 예외 승인, CI+Vercel 증거로 릴리스 검증 완료.

**조사**: `cmd_observe`는 순수 로컬(파일 쓰기·검증)이라 코드상 블로킹 지점 없음. `wrap --strict`·훅 경로에도 `input()`류 프롬프트 없음 — **행 자체는 상류에서 재현 불가**(다운스트림 환경 이슈 추정: 샌드박스 권한 프롬프트 등). 단 "pre-push 검증은 결정적으로 끝나야 한다 + 우회는 흔적을 남긴다"는 원칙은 코드와 무관하게 타당하고, 현행 훅은 `--no-verify` 우회가 무기록.

**판정 초안**: 유효 — 단 **설계 결정 동반**(사람): 타임아웃 시 fail-closed 유지(무한 대기만 제거) 권고. 폴백을 자동 fail-open으로 하면 가드 무력화. **분배 권고**: 훅 본문에 `timeout` 래퍼 + 타임아웃/우회 시 "사유를 관찰로그 friction으로 기록" 안내 출력. *대안*: 재현 불가를 근거로 만료 처리(원칙 부분만 지침 07/23에 한 줄).

## 4. land-merge-error-misreport (gamblescan → tool/land)

**제안**: land 4/6이 GitHub 머지 성공 + 로컬 동기화 실패(`main is already used by worktree`)를 "머지 실패—충돌·권한·보호 규칙 확인"으로 오진 보고 → 재시도 시 이중 머지·불필요 롤백 위험. 머지 API 성공/로컬 동기화 실패를 분리 보고, worktree 점유 시 해당 worktree에서 ff-pull 하거나 `--no-sync`. 덤: squash 머지라 maincheck가 원본 SHA로는 실패 → land가 squash SHA 출력.

**조사**: 현행 코드에서 **전부 확인됨** — ① 4/6: `gh pr merge --squash --delete-branch` rc≠0이면 일괄 "머지 실패" 보고(`--delete-branch`의 로컬 checkout 실패도 여기 포함됨), ② 5/6: `git checkout main`의 rc 자체를 무시, ③ 6/6: maincheck를 `rev-parse HEAD`로 수행 — checkout이 실패한 채로는 HEAD가 원본 브랜치 SHA라 squash 머지 도달을 영원히 미도달로 판정. PR gamblescan#309(cd3de7b)가 실사례.

**판정 초안**: 유효(재현 확인). **분배 권고**: `land` 수정 — 머지 단계에서 gh 종료코드와 무관하게 **PR 머지 상태를 API로 재조회**해 머지/로컬정리 실패를 분리 보고, 5/6 checkout 실패(worktree 점유) 시 명시 안내+`--no-sync` 경로, 6/6은 `gh pr view --json mergeCommit`의 squash SHA로 maincheck + 출력. 도구 변경이므로 negative case 실효 증명(지침 23 §1-3) 동반.
