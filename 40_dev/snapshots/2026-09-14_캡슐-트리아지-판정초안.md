## A. 병렬 세션 경합 — 7건 묶음 (#1~#7)

icons 에서 5건, cafe24 에서 1건, 그리고 지침 30 자체가 지난 회차에 이 축으로 신설됐다. 근거가 정량적이다 — **2026-09-07~09 PR 13건 중 11건이 라이브 파일·생성물 충돌로 리베이스, 내용 충돌은 0건**(#2). #907 은 리베이스→푸시 6회 전부 CI 잡 steps=0 실패(#3). 같은 구조의 사고를 도구 4개(ship·land·wrap·todo)와 지침 30 이 각각 절반씩 안고 있다.

**상류 실측**: `.gitattributes` 없음 · `.gitignore` 는 `wrap-state.json`·`prompting-report.md` 를 제외하지 않음(ship 이 매 커밋 포함) · land 는 `mergeable` 을 조회하지만 DIRTY 분기 없음 · CI 판정은 pending/failing 2분류뿐(잡 steps=0·annotations 미판독) · ship 의 기본 경로 `add -A` 는 미추적 파일 열거 없음(METH-142 가드는 `--no-add-all` 경로만) · TODO ID 예약 명령 없음.

### A-1. 충돌 표면 줄이기 (#1·#2)
- **`prompting-report.md` 커밋 제외** — 관찰로그에서 파생되는 순수 생성물이라 gitignore + boot/wrap 재생성이 안전하다. 채택 권고.
- **`wrap-state.json`** — ship 주석대로 «라이브 파일과 같은 커밋에 패키징»되어야 clone 후 wrap 이 일관된다. 제외하면 baseline 을 HEAD 의 파일 sha 로 *재계산*하는 설계 변경이 필요하다. **사람 판단 ①** — 권고안: 재계산 설계로 전환(wrap-state 는 캐시로 강등, 없으면 HEAD 에서 계산). 근거: 이 파일이 충돌의 절반이고 내용 가치는 0 이다.
- **`.gitattributes merge=union`**(TODO·HANDOFF·checkpoint) — 삽입 지점 충돌을 없애지만 union 은 줄을 *합치기만* 해서 Working-on 중복·Done 항목 중복이 생길 수 있다. 다만 **METH-143 wrap 구조 검증이 정확히 그 중복을 error 로 잡는다** — 안전망이 이미 있다. **사람 판단 ②** — 권고안: 채택하되 checkpoint 는 제외(세션 바통은 «덮어쓰기»가 의도라 union 이 뜻을 깨뜨린다).
- checkpoint 세션별 파일(#1 ②)은 **비채택** 권고 — 바통은 하나여야 콜드스타트가 성립한다. 충돌은 union 대신 «리베이스 시 내 것 유지» 규칙(지침 30 v3, #6)으로 푼다.

### A-2. land 의 경합 인식 (#1 ③·#3)
- **DIRTY 감지 → `origin/main` 자동 머지→재푸시→재시도 1회** — 채택 권고. land 는 이미 `mergeable` 을 읽고 있어 분기 하나로 끝난다.
- **잡 steps=0 실패를 「경합」으로 분류하고 CI 1사이클(≥2분) 대기 후 재판정** — 채택 권고. 「내용 실패」와 구분해 보고하지 않으면 사람이 로그 없는 실패를 들여다보느라 시간을 쓴다(#907 실측).
- **「로컬 검증 통과한 Class A 문서 PR 은 CI 미대기 즉시 머지」 — 비채택 권고.** ADR-004 의 «Class A + CI green 일 때만»을 깨는 경로다. 경합은 위 두 장치로 풀리고, CI 가 아예 없는 경우는 #8 의 규율화된 `--local-ci` 가 맡는다. 예외 경로를 하나 더 열면 그것이 기본이 된다.

### A-3. ship 의 공유 체크아웃 인식 (#4)
ship 은 «누구 파일인지» 알 수 없다. 그래서 **감지 + 열거 + 확인**으로 간다: `git worktree list` 가 2개 이상이고 현재가 주 체크아웃이면 «공유 체크아웃»으로 보고, 커밋 직전 미추적·미커밋 파일 목록을 출력하며 `--allow-shared` 없이는 거부한다. 정본 해법은 지침 30 §1(격리 워크트리)이고 ship 은 그 규율의 마지막 방어선이다. 채택 권고.

### A-4. 원자적 ID 예약 (#5·#7)
**사람 판단 ③** — 두 안: (a) 세션 접미사 ID(`METH-148a`)는 안정 ID 원칙(지침 02)을 깨고 대시보드 파싱을 흔든다. (b) **원격 태그 예약** — `methodology.py reserve` 가 origin/main·로컬을 스캔해 다음 번호를 고르고 `refs/tags/id/METH-148` 을 push 한다. 태그 생성은 원격에서 원자적이라 동시 두 세션 중 하나만 성공한다. 권고안 (b). #7(Blocked 등록 전 기존 항목 grep + 월 1회 stale 대조)은 규칙이라 CLAUDE.md §2 Blocked 문단 한 줄.

### A-5. 리베이스에서 라이브 파일 유실 (#6)
land 는 리베이스를 하지 않으므로 도구 변경은 보류. **지침 30 v3** 에 절 신설: 리베이스 충돌에서 라이브 파일 일괄 `ours` 금지(리베이스 중 ours = upstream) · HANDOFF 줄은 재삽입 · checkpoint 는 치환이 아니라 prepend · 리베이스 직후 `wrap` 으로 4/4 확인.

## B. CI 부재 시 로컬 재현 게이트 (#8, 유효·설계 동반)

PM 이 결제를 풀지 않기로 명시(08-20·09-09)한 상태에서 CI green 규칙을 그대로 두면 모든 PR 이 멈춘다. 캡슐의 절차는 이미 규율적이다 — annotations 로 원인 확인 → PM 판정을 Blocked 에 박제 → CI 단계를 로컬에서 그대로 재현 → 통과 시에만 `--no-ci-check` → PR 본문 명기 → 복구 시 원복.
**분배**: land `--local-ci` — ① annotations 에 billing/infra 사유가 있는지 확인 ② TODO Blocked 에 PM 판정 항목이 있는지 grep(없으면 거부) ③ CI 워크플로의 단계를 로컬 실행 ④ 통과 시 머지하고 PR 본문에 자동 기입. `--no-ci-check` 의 규율화된 형태이며 fail-closed 는 유지된다.

## C. 도구 단건 3 (#9·#10·#19)

- **#9 observe 세로줄** — `parse_friction` 이 `raw.split("|")` 로 4필드를 요구해 resolution 본문의 `|` 가 형식 오류를 낸다. 지난 세션 내 관찰로그에서도 grep 인용문을 피해 썼다. 수정: `repeat_of` 는 `rsplit("|",1)`, `where`·`cost` 는 `split("|",2)` — 가운데 resolution 은 세로줄 허용. 즉시 유효.
- **#10 테스트 판정 grep** — 상류 ship 은 `subprocess.call([manager,"run","test"])` 의 **exit code** 로 판정한다. 캡슐의 사고는 하류 test 스크립트 체인(`| grep 통과`)에서 났다. 도구는 이미 반영. 원칙 «출력 문자열이 아니라 exit code 로 판정, 성공 토큰만 인정»은 지침 23 §1-4(대리 신호)의 인스턴스로 1줄.
- **#19 boot 배포 접속 preflight** — boot 에 선언 파일 검사 없음. `.methodology-version` 에 `required_local_files: [...]` 를 두면 boot 가 **존재만** 검사해 경고(내용은 읽지 않는다 — 비밀). 월 4회·반나절 미배포가 근거. 채택 권고.
