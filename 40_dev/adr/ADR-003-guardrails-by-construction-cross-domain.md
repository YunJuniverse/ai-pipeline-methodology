# ADR-003 백서에 Guardrails-by-Construction을 횡단 운영 원칙(§8-5)으로 격상한다

백서(`10_foundation/WHITEPAPER.md`)에 운영 원칙 **§8-5 Guardrails-by-Construction**을 신설하고 버전을 v0.2.0 → v0.3.0으로 올린다. 품질·안전 규율을 *사후 정리*가 아니라 *발생 방지*로, 프롬프트·리뷰가 아니라 *시스템(린트·CI)으로 fail-closed* 강제한다는 원칙을 — 지금까지 *AI 안전*(지침 17 §4.2)에만 적용하던 것을 — **AI 안전 + 코드 품질(지침 19) 공통 원칙**으로 명문화한다.

## Context

- METH-047로 지침 19(클린아키텍처·클린코드)를 신설(적용 프로젝트 GambleScan REFACTOR-CLEAN ~50 PR 환류). 그 핵심 통찰은 "첫날부터 가드레일이 `error`였다면 부채가 안 쌓인다"이며, 이는 지침 17 §4.2의 *AI 안전* 가드레일 원칙과 **같은 원리**였다.
- 사용자가 "방법론 백서와 가이드라인을 이 클린코드·클린아키텍처 기반으로 업데이트하라"고 지시 → 코드 품질을 방법론 표준 서사로 통합.
- 백서는 헌법이므로 §12에 따라 변경은 Class C(ADR + 인간 승인). 본 ADR이 그 근거다.

## Considered Options

- **§8-5 신규 운영 원칙으로 격상 (채택)** — 가드레일 우선 원리를 헌법 레벨로 올려 *모든* 가드레일(AI 안전·코드 품질·향후 확장)의 상위 근거로 삼음. 비용: 헌법 변경(Class C). 이득: 일관된 원리·중복 제거.
- 백서는 그대로 두고 지침 19/백서_가이드에만 기술 — 헌법 변경 회피. 단점: 횡단 원리가 헌법에 부재해 "왜 두 영역에 같은 규율인가"의 상위 근거가 흩어짐.
- 별도 신규 백서 절(§14) — 과함. 기존 §8 운영 원칙에 자연 귀속.

## Decision

- 백서 §8-5 신설(강제 위치=시스템 / 장애모드=fail-closed / 래칫 도입 / AI안전·코드품질 동일 적용).
- 버전 v0.3.0(§12: 운영 메커니즘 변경 = MINOR). 부록 A에 지침 19 행 추가(PATCH).

## Consequences

- 쉬워지는 것: 신규 가드레일 도입 시 근거가 단일(§8-5) — 지침 17·19가 이를 인스턴스화.
- 어려워지는 것: 없음(원리 명문화일 뿐, 신규 강제 추가 아님).
- 후속: 가드레일을 끄거나 우회하는 변경은 ADR 근거 필요(백서·지침 19 명시).
- **선행조건**: 없음 — 지침 19·17은 이미 존재.
- **되돌리기 비용**: 낮음(원칙 1개 절). 단 헌법이라 변경 자체는 Class C 절차를 거친다.
