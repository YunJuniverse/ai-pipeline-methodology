# ADR-007: land 머지 기록 커밋 폐지 · 전파 대상 축소 · 산문 규칙 슬림화 방향

## Status

accepted

## Date

2026-11-25

## Approval

사용자 채팅 승인, 2026-11-25: 30일 커밋 집계 결과와 D1~D3 을 제시했고 «전부 채택»으로 답했다. 반영은 TODO METH-152. 이 ADR 이 머지되는 PR 이 CLAUDE.md §3 Class C 의 «명시적 사람 승인 증거»다.

## Context

ADR-006(2026-11-09) 적용 뒤 16일 시점에, 로컬에 있는 전 레포의 최근 30일 커밋을 origin 기본 브랜치 기준으로 집계했다(2026-11-25). 집계는 커밋 수뿐이며 토큰·시간 비용과 사고 건수는 재지 않았다.

- **일의 대부분이 방법론 밖에서 일어난다.** 30일 커밋은 방법론 적용 레포 8곳 354건, 미적용 레포 4곳 1,188건이다(23% : 77%). 커밋이 가장 많은 네 곳이 모두 미적용이다.
- **머지 기록 커밋이 PR 과 1:1 로 쌓인다.** ADR-006 D2 로 기록 전용 PR 은 줄었지만 기록 커밋 자체는 남았다. 적용 레포 전체에서 약 30건(8%), 레포별로는 2%~38%이고, 한 레포는 하루에 PR 14건에 기록 커밋 14건이 붙었다.
- **D2 가 고르게 지켜지지 않는다.** ADR-006 이후에도 기록 전용 PR 이 한 레포에서 2건 올라갔고, 다른 레포는 PR 59건에 기록 커밋이 1건뿐이다. 같은 규칙이 레포마다 다르게 돈다.
- **전파 대상의 절반이 휴면이다.** 관리 다운스트림 13곳 중 7곳은 30일간 커밋이 방법론 sync 하나뿐이다. sync 1회는 활동 레포 한 곳 기준 15개 파일, +673줄이다.
- **지침 분량.** `20_guides/` 32개 파일, 10,726줄. CLAUDE.md §2 는 사고 하나당 규칙 하나가 누적된 산문이다.

머지 기록이 생긴 원래 이유는 둘이다. ① «머지됨»이라 했는데 main 에 코드가 없던 실사고(METH-120) ② PR 안에서는 머지 사실을 미리 쓸 수 없다는 전제. ①은 `maincheck` 가 막고, ②는 전제가 틀렸다 — Done 전이를 PR 에 실으면 main 에 못 간 PR 은 Done 도 main 에 못 간다.

## Decision

1. **D1 land 머지 기록 커밋을 폐지한다(ADR-006 D2 대체).**
   - TODO 의 Done 전이와 HANDOFF Recent 한 줄은 **그 작업의 PR 안에** 싣는다.
   - `land` 는 머지 → 기본 브랜치 동기화 → `maincheck` 까지만 하고, 결과는 출력으로만 보고한다. 커밋을 만들지 않는다.
   - TODO 의 `landed` 줄을 없앤다. 머지 sha 는 git 히스토리에서 찾는다.
   - «main 직접 push 금지»의 예외(`chore(land):`)를 삭제한다 — 예외가 0개로 돌아간다.
   - `maincheck` 실패 시 land 가 비정상 종료하고, 그 PR 의 Done 표기가 main 에 없음을 알린다.
2. **D2 전파는 활동 레포에만 한다.**
   - `sync-all` 은 최근 30일 내 커밋이 있는 다운스트림만 대상으로 삼는다(sync 커밋 자체는 활동으로 치지 않는다).
   - 휴면 레포는 다음에 세션이 열릴 때 `boot` 가 버전 차이를 알리고, 그때 그 레포에서 sync 한다.
3. **D3 산문 규칙은 «도구가 강제하는가»로 가른다(방향만 결정, 실행은 METH-153).**
   - 도구가 fail-closed 로 막는 규칙(`ship`·`land`·`maincheck`·pre-push 훅)은 CLAUDE.md 에 한 줄 포인터만 남긴다.
   - 모델이 기억해서 지켜야 하는 산문 규칙은 최근 전수조사에서 위반·재발 근거가 있는 것만 남기고 나머지는 지침 본문으로 내린다.
   - 목표 분량과 삭제 목록은 이 ADR 에서 정하지 않는다 — 후속 TODO 에서 목록을 만들어 다시 승인받는다.

## Consequences

- 적용 레포의 커밋 수가 PR 수에 가까워진다. main 에 AI 가 직접 push 하는 경로가 없어진다.
- Done 표기가 머지보다 먼저 쓰인다 — 열린 PR 의 브랜치에서 TODO 를 보면 아직 머지 안 된 항목이 Done 으로 보인다. main 의 TODO 만 사실로 본다.
- 여러 PR 이 동시에 TODO.md·HANDOFF.md 를 고치므로 충돌이 늘 수 있다. 지금은 land 가 머지 후 순차로 써서 충돌이 없었다.
- ADR-006 D2 의 폴백(브랜치 보호 레포는 다음 PR 에 기록)과 `land --no-record` 가 불필요해진다.
- 휴면 레포는 방법론 버전이 뒤처진 채로 남는다. 세션이 열리기 전까지는 무해하다.
- D2 로 thinktank 의 «전파 n/n» 지표 분모가 바뀐다 — 이 ADR 날짜를 경계로 읽는다.

## Rejected alternatives

- **현행 유지(ADR-006 D2)** — 기록 전용 PR 은 줄였지만 PR 당 커밋 1건과 main 직push 예외가 남고, 레포마다 준수가 갈린다.
- **TODO 상태를 파일에서 빼고 GitHub 이슈로만 관리** — 부팅 프라이머(HANDOFF·TODO)가 오프라인 파일이라는 전제를 깨고, 대시보드 파싱도 다시 짜야 한다. 이번 범위 밖.
- **방법론 레포 아카이브(동결)** — 미적용 레포에서 사고가 더 났는지 재지 않았고, `maincheck`·ship 가드 같은 실행 장치는 모델 성능과 무관하게 싸다. 근거가 부족하다.
- **기록 커밋을 하루 1건으로 묶기** — 커밋 수는 줄지만 `landed` 필드·직push 예외·준수 편차가 그대로 남는다.

## Open questions

- 미적용 레포 4곳에 얇은 판(가드 도구 + 한 페이지 규칙)을 제안할지 — D3 의 결과물을 보고 판단한다.
- D1 적용 시 이미 쌓인 `landed` 줄을 지울지 그대로 둘지.
