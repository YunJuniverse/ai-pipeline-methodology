# AI 기획·개발 방법론 — 백서 겸 가이드

> **한 줄 요약**
> *"같은 문제에 두 번 부딪히지 않는, 도구에 종속되지 않는, 누구든 즉시 이어받는 1인+AI 작업 자산 시스템."*
> 도구는 갈아탈 수 있고, 자산은 남는다.

이 문서는 방법론의 **철학(왜)** 과 **사용법(어떻게)** 을 한 편으로 정리한다. 더 깊은 시스템 헌법은 [`WHITEPAPER.md`](WHITEPAPER.md), 도메인별 작성 표준은 [`20_guides/`](../20_guides/), 재사용 템플릿은 [`50_resources/templates/`](../50_resources/templates/)에 있다.

---

## 1. 왜 — 해결하려는 문제

소규모·다도메인으로 일하는 1인 창업자/소수 팀은 세 가지 비효율을 반복한다.

1. **반복 마찰** — 스택·도메인이 달라 보여도 시간을 잡아먹는 함정은 놀랍도록 자주 똑같다. 매번 처음 보듯 같은 곳에 빠진다.
2. **암묵지 단절** — 프로젝트가 "산출물 1건"으로 끝나며, 그 과정의 노하우(무엇이 잘 됐나, 어떤 결정이 후회로 이어졌나)가 다음으로 이전되지 않고 휘발한다.
3. **AI·환경 휘발성** — 모델은 빠르게 교체되고, 도구(Claude Code/Cursor/Codex)는 인터페이스가 다르며, 작업자는 여러 PC를 오간다. 한 도구·한 모델에 종속된 워크플로는 6개월 안에 부패한다.

방법론은 이 셋을 **단일 자산 저장소**로 흡수해, 다음 작업이 항상 *지난 작업의 잔재 위에서* 시작되게 한다.

## 2. 핵심 철학 — 3대 원칙 (충돌 시 위가 강함)

### 제0원칙 · 이식성 (Portability First)
> 도구는 갈아탈 수 있다. 자산은 남는다.

어떤 AI·어떤 PC·어떤 시점에 누가 이어받든, **저장소 하나로 같은 컨텍스트에 즉시 진입**한다. 특정 도구에 종속된 자동화는 코어가 아니라 *어댑터*로 격리한다.

### 제1원칙 · 비반복 (No Twice Hit)
> 같은 문제에 두 번 부딪히지 않는다.

한 번 해결한 문제는 다음에 다시 발견 가능해야 하고, 반복 확인된 문제는 다음 시작 시점에 *해결책이 적용*돼 있어야 한다. 적어두는 것만으론 부족하다 — **적용까지가 학습**이다.

### 제2원칙 · 인계 가능성 (Handoff-Ready by Default)
> 이 자산을 상속받은 누구든, 과거 시행착오 비용을 0으로 시작한다.

6개월 뒤의 나도 "다른 사람"이다. 모든 자산은 *인계 시점*을 가정하고 쓴다. 판정 기준: **15분 안에 첫 의미 있는 작업을 시작할 수 있는가?**

## 3. 거버넌스 — 인간이 게이트를 쥔다

AI가 자기 자신을 마음대로 바꾸지 않는다. 모든 의미 있는 변경은 **사람의 게이트**(머지된 PR / ADR / 이슈 승인)를 통과한다.

### 변경 클래스 (Change Class)
| 클래스 | 대상 | 게이트 |
|---|---|---|
| **A** | 일반 기능·문서·리팩터·버그픽스 | 머지된 PR |
| **B** | DB 스키마·외부 API 계약·인증·파괴적 변경·백그라운드 작업 | PR + 근거·영향·롤백·리스크 명시 |
| **C** | 가격·법무·브랜드·공개 릴리스·외부 약속 | 구현 중단 → ADR → 명시적 인간 승인 후에만 |

> AI는 A를 B/C로 *격상*할 수 있으나, 자동 B/C 트리거를 *조용히 강등*하지 못한다.

### 진실의 원천
- **코드** = 구현의 진실 (문서와 충돌 시 코드가 이긴다)
- **ADR** = 코드가 설명 못 하는 *결정*의 진실 (되돌리기 어렵고 트레이드오프가 있는 것만)
- **인간 승인** = 머지된 PR·링크된 승인 증거로만 실재. "승인했다"는 말은 증거가 아니다.

### 라이브 상태 파일 (단 하나의 살아있는 진실)
- `HANDOFF.md` — 현재 포커스·최근 검증·다음 액션 (150줄 한도)
- `TODO.md` — 활성 백로그 (안정 ID·수용 기준)
- `.ai/checkpoint.md` — 다음 사람/AI를 위한 1페이지 인계서
- 산출물(`snapshots/`)은 *날짜 박힌 스냅샷* — 절대 라이브로 승격 금지

## 4. 시스템 구조 — 5계층 + 폴더 규칙

```
L4. 대시보드 + 온보딩      ← 사람을 위한 단일 진입점
L3. 씽크탱크 (마이닝)      ← 패턴 마이닝 → 제안 (자동 적용 없음)
L2. 활성 자산 (Catalog/템플릿/Skeleton) ← 다음 작업이 실제로 쓰는 것
L1. AI 관찰 로그 (raw)     ← 매 세션 자동 기록
L0. 이식성 코어 (.ai/, HANDOFF) ← 어떤 AI/PC도 즉시 부팅
```

**폴더 번호 컨벤션** (Johnny.Decimal 변형 — 십의 자리 = 워크플로 단계):

| 번호 | 폴더 | 용도 |
|---|---|---|
| 00 | `00_briefs/` | 인간 raw 입력(아이디어·리서치·회의록) — AI 매 세션 읽음 |
| 10 | `10_foundation/` | 백서·온보딩·헌법 |
| 20 | `20_guides/` | *어떻게 쓰는가* — 도메인별 작성 지침 |
| 30 | `30_planning/` | *무엇을 썼는가* — 실제 기획 산출물 (20과 끝번호 페어링) |
| 40 | `40_dev/` | 마스터플랜·ADR·스냅샷 |
| 50 | `50_resources/` | 템플릿·프롬프트·Catalog·관찰 로그 |
| 60 | `60_tools/` | `methodology.py` CLI·대시보드 |
| 70 | `70_meta/` | 메타-방법론 (자기 진화) — **외부 프로젝트에 주입 안 됨** |
| 90 | `90_archive/` | 아카이브 |

## 5. 기획·개발 craft — 방법론의 콘텐츠

방법론은 *시스템*만이 아니라 **실전 기획·개발 craft**를 담는다. 적용 프로젝트(ICONS·GambleScan·icons-ip)와 원본 학습 코퍼스에서 정제한 일반 craft가 지침(`20_guides/`) §19 "실무 craft 부록"과 템플릿에 축적돼 있다.

### 지침 체계 (`20_guides/`)
- **00~03** 공통: 운영 원칙·오케스트레이션·식별자/버전·관찰 로그 규칙
- **10~16** 도메인별: 사업·서비스·운영·마케팅·브랜드·프로젝트관리·AI기능 기획서
- **17~19** 평가·가드레일 / 개발 마스터 플랜 / **클린아키텍처·클린코드 개발 규칙**

각 기획 지침의 **§19(현장 craft)** 에 적용 프로젝트 환류분이 쌓인다. 예: 사업기획의 *검증 우선순위 게이트·KPI 단위경제 트리·규제 전제 게이팅·아이디어 비판검증 3분류*, 서비스기획의 *ASIS→TOBE·12단계 산출물·다면 권한 매트릭스·요구사항 4층 추적(BR→UR→FR→NFR)*, 마케팅의 *Triple Media·4유발 퍼널·채널 운영 플레이북*, PM의 *WBS·제안 5단계·n(n−1)/2 채널공식·RACI*.

### 핵심 관통 패턴 (기획)
- **근거 없는 산출물 금지** — 모든 화면·정책·기능은 *ASIS 문제점 → 개선*으로 정당화. 요구사항은 Needs(What)가 아니라 Purpose(Who·How)로 받는다.
- **측정 가능성** — 추상어("빠른") 대신 수치("평균 12분"·"로드 2초"). 목적은 정성, 기대효과는 그 정량화.
- **다면(N-sided) 시장** — 각 면의 가치 흐름·비대칭 권한·콜드스타트를 명시적으로 설계.
- **거버넌스·추적** — DoR/DoD·요구사항 추적 매트릭스·승인 로그·서명 sign-off로 결정의 수명주기를 감사 가능하게.

### 코드 품질 craft — Guardrails by Construction (지침 19)
fullstack/dev 트랙은 **첫날부터** 코드 품질을 *린트 가드레일로 fail-closed 강제*한다 — 사후 리팩토링(아키텍처 부채 정리)을 *애초에 발생하지 않게*. 이는 지침 17 §4.2의 *AI 안전* 가드레일 원칙을 *코드 품질*에 인스턴스화한 것(적용 프로젝트 GambleScan REFACTOR-CLEAN ~50 PR 환류).
- **4-레이어 의존성 규칙**: domain(순수, IO 없음) ↛ infra/app/interface · 라우트·컴포넌트는 DB 직접 호출 금지 → use case·서버액션 경유.
- **4 코드 가드레일**(린트 `error`): 레이어경계 · `no-explicit-any`(→`unknown`+가드) · `no-console`(단일 logger sink) · `max-lines=400`(god파일 분할).
- **래칫 원리**: day-1 `warn` 베이스라인 → 카테고리별 0 수렴 → `error` 승격(역행 불가). `any`는 단순 느슨함이 아니라 *버그 은폐 장치* — 타입 정직화가 곧 버그 발굴이다.
- 도메인 순수로직 100% 테스트 목표 · 비즈니스 로직 변경은 테스트 동반.

## 6. 템플릿 라이브러리 (25종) + 작업 모드 (6모드)

템플릿은 `50_resources/templates/`에 flat하게 있고, **작업 모드별 선택**은 [`_CATALOG.md`](../50_resources/templates/_CATALOG.md)가 정본이다. *모든 작업에 모든 템플릿을 쓰지 않는다 — 모드에 맞는 세트만 로드한다.*

| 모드 | 용도 | 핵심 세트 |
|---|---|---|
| **planning** | 기획전용 | prd · requirements-spec · ia-spec · service-policy · user-story · kpi-tree · context-glossary · microcopy |
| **dev** | 개발전용 | architecture · data-model · user-flow · wireframe-spec · functional-spec |
| **fullstack** | 기획+개발 | planning ∪ dev + wbs |
| **agency** | 외주(수주·납품) | 제안(go-nogo·자료수집) · 수익율관리 · 수행계획서 · 검수 3종 · 운영명세 · 모니터링 · 업무요청 · 용어집 |
| **lean** | 1인+AI 빠른 반복 | prd · architecture · context-glossary · ADR |
| **ops** | 런칭 후 운영 | 운영명세 · 모니터링 · 업무요청 · 검수 3종 |

**카테고리**: 기획(8) · 개발명세(5) · PM(1) · 제안/수주(4) · 검수(3) · 운영(4). 경량 모드는 `PRD(무엇) + ARCHITECTURE(어떻게) + CONTEXT(용어집)` 3문서로 풀 기획서군을 대체한다.

## 7. 워크플로 — 부팅부터 마감까지

```
부팅:  CLAUDE.md + HANDOFF.md 로드 → 00_briefs 읽기 → checkpoint 확인 → 대시보드
작업:  TODO 1건 선택 → 모드별 필요 템플릿만 로드(_CATALOG) → 변경 클래스 판정
       → 구현(테스트 우선 + 지침 19 가드레일 준수) → lint·typecheck·build·test 게이트 → PR (main 직접 push 금지)
승인:  사람이 PR 리뷰·머지 (= 유일한 진짜 승인 게이트)
마감:  TODO·HANDOFF·checkpoint 갱신 + 관찰 로그(CLI) → wrap 검증(4/4) → ship(commit+push)
```

- **세션 마감은 의무**: 라이브 4파일 갱신 후 `python3 60_tools/methodology.py wrap`이 `4/4 ✓`일 때만 종료. `ship`이 wrap+sensitive검사+commit+push를 일괄 처리.
- **인간 승인 게이트**: 연구→기획→개발명세→빌드→피드백 각 단계 전환은 사람의 명시 지시·머지 증거가 있어야 넘어간다. AI는 "준비됨"을 *제안*만 한다.
- **day-1 코드 가드레일(fullstack/dev)**: 신규 프로젝트 `init` 직후 지침 19 §9 체크리스트로 4-레이어 + 4 린트 가드레일(`warn`→래칫→`error`)을 깐다. 코드 품질은 리뷰 구두 지적이 아니라 *린트가 fail-closed로 강제*.

## 8. 자가발전 — 사람 게이트를 가진 패턴 마이닝

```
작업 수행 → L1 자동 관찰 기록 → L3 마이닝 → 승급 후보 PR
        → (사람 머지) → L2 Catalog 갱신 → 다음 작업이 자동으로 더 나아짐
```

이건 "강화학습"이 아니다. **사람이 게이트를 쥔 패턴 마이닝 + 결정적 자산 합성**이다. 동일 마찰이 N≥2회 목격되거나 사람이 승인하면 관찰이 Catalog로 *승급*된다. 6개월 미사용 자산은 자동 아카이브된다. 과장된 명명("자율"·"지능형")을 쓰지 않는 *정직한 명명*이 안전성을 보장한다.

## 9. 멀티프로젝트 전파 + 메타 격리

방법론 저장소는 **두 역할의 재귀 구조**다.
1. **외부 프로젝트가 적용하는 원천** — `methodology init`/`sync`로 주입되는 자산(`20_guides`·`50_resources`·`60_tools`).
2. **자기 자신을 진화시키는 메타-방법론** — `70_meta/` (RFC·회고·실험·메타 관찰). **외부 주입 절대 안 됨**(2중 안전망: whitelist + `excluded_paths` 검증, CI 차단).

업스트림(이 저장소)이 정본이고, 다운스트림은 `sync --apply`로 공유 자산을 수령한다. *프로젝트 고유 자산은 보존*하는 것이 원칙이다.

## 10. 시작하기

```bash
# 1) 새 프로젝트에 적용
python3 60_tools/methodology.py init --path <project>

# 2) 부팅(매 세션) — 대시보드
python3 60_tools/methodology.py dashboard      # http://localhost:8765

# 3) 작업 모드 선택 → CLAUDE.md §1 Mode 기입 → _CATALOG.md 의 해당 세트만 로드

# 4) 세션 마감
python3 60_tools/methodology.py observe --slug "<slug>" --task-type <type> --summary "<50~150자>"
python3 60_tools/methodology.py ship -m "<conventional commit>"
```

부팅 순서: **`README.md` → `ONBOARDING.md` → 본 문서/`WHITEPAPER.md`**. 첫 작업 시작까지 15분, 도메인별 첫 PR까지 1일이 목표.
